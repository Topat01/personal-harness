# 문제 꼴별 알려진 방법 (참고용)

> 후보 해법을 고를 때 같은 꼴을 찾아 **알려진 기준선부터** 시작한다. 이 문서는 방법 이름과 쓰임새, 평가 함정만 적는다. 코드는 없다.
> 원칙: ① 단순한 기준선을 먼저 만들고 같은 `evaluate`로 비교한다. ② 새 라이브러리 설치는 사람에게 먼저 묻는다. ③ 고른 방법을 내 말로 설명할 수 있어야 한다.

---

## 1. 이상 감지 (시계열·센서·설비)

| 상황 | 기준선 | 강한 방법 | 비고 |
|---|---|---|---|
| 단일 시계열, 평균 이동·튐 | 이동 중앙값 + **MAD 기반 robust z**, SPC 3σ·Western Electric 규칙 | EWMA·**CUSUM**(작은 지속 이동에 강함), STL 분해 후 잔차 감지 | 설비·레시피별로 기준선을 따로 둔다 |
| 단일 시계열, 모양 이상 | 계절 대비 차이 | **Matrix Profile**(discord 탐색, `stumpy`) | 길이 하나만 정하면 되고 설명이 쉽다 |
| 다변량 센서 | 변수별 z-score | **PCA + Hotelling T²·SPE(Q)**, Mahalanobis, **Isolation Forest** | 공정 현업에서 오래 써 온 방법은 PCA T²/SPE |
| 라벨 일부 있음 | 임계값 튜닝 | 지도 학습(GBM) + 불균형 처리 | 시간 순서로 나눠 검증 |

**평가 함정**
- **point-adjust**(구간 안 한 점만 맞혀도 구간 전체를 맞힌 것으로 치기)는 점수를 크게 부풀린다. 이벤트 단위 F1이나 PR-AUC를 쓴다.
- 공개 시계열 이상 감지 벤치마크는 결함이 많다는 지적이 있다(Wu & Keogh, 2021). **딥러닝이 단순 기준선을 못 이기는 경우가 흔하다** → 기준선과 반드시 비교한다.
- 알림 피로: 정밀도, 하루 알림 수, 첫 감지까지 걸린 시간을 함께 본다.

## 2. 원인 찾기 (수율·불량)

| 방법 | 쓰임 |
|---|---|
| **공통성 분석** | 불량 로트가 공통으로 거친 장비·챔버·시간대 찾기. 반도체 현업의 기본 |
| 그룹별 비교 + 검정 | χ²·Fisher(불량 비율), Kruskal–Wallis(연속값). **다중 비교 보정(Benjamini–Hochberg)** |
| 트리 모델 + SHAP | 변수 중요도 탐색. 인과가 아니라 후보 순위 |
| 시점 전후 비교 | 변경점(장비 PM, 레시피 변경) 전후 차이 |

**함정:** 표본이 적은 그룹의 극단값, 상관과 인과, 교란(같은 시간대에 여러 변경), 결과를 보고 만든 규칙을 같은 데이터로 평가하기.

## 3. 웨이퍼 맵 패턴

- 기준선: 기하 특징(반경 분포, 사분면 비율, 연결 성분 크기·모양, Radon 변환) + 랜덤 포레스트·SVM
- 강한 방법: CNN(공개 WM-811K에서 높은 정확도 보고)
- 함정: 클래스 불균형(정상이 대부분), 혼합 패턴. 클래스별 재현율과 혼동 행렬로 본다.

## 4. 차량 경로 (VRP, 셔틀·물류)

| 기준선 | 강한 방법 |
|---|---|
| sweep(각도 정렬 후 용량까지), **Clarke–Wright savings** | 지역 탐색(2-opt, relocate, swap), **OR-Tools Routing(guided local search)**, 최상위권은 HGS(Vidal)·LKH-3 |

**함정:** 시간창, 최대 탑승 시간, 비대칭 소요시간, 너무 잘게 쪼갠 노선(퇴화).

## 5. 커버리지·배치 (카메라·센서·정류장·시설)

| 문제 | 방법 |
|---|---|
| 최대 커버리지(k개로 최대한 덮기) | **그리디**(근사 보장 1−1/e), lazy greedy로 빠르게, 정수계획(ILP)으로 소규모 최적 확인 |
| 집합 덮기(전부 덮는 최소 개수) | 그리디(ln n 근사), ILP |
| 카메라 가시성 | 격자로 칸을 나누고 시야각·벽 차단으로 덮는 칸을 계산한 뒤 최대 커버리지. 고위험 칸에 가중치 |
| 시설 입지(p-median) | 그리디 + 맞바꾸기(Teitz–Bart) |

**함정:** 전부 설치(비용 무시), 한 구역 몰빵, 중복 감시를 커버리지로 이중 계산.

## 6. 스케줄링·디스패칭 (장비, PM, Q-time)

| 방법 | 쓰임 |
|---|---|
| 디스패칭 규칙 | FIFO, EDD(납기), 최소 여유(slack), CR, **ATC**(납기 + 가중치) |
| Q-time 대응 | 다음 공정 여유를 보고 앞 공정 투입을 늦추기(투입 통제), WIP 상한(CONWIP) |
| 이벤트 시뮬레이션 | 규칙 여러 개를 같은 시나리오로 비교. 그 자체가 `evaluate` |
| **CP-SAT(OR-Tools)** | 작은 잡숍·PM 일정 최적해, 규칙 결과의 상한·하한 비교 |

**함정:** 장비 놀림(Q-time만 지키려 투입 정지), 우선 로트 기아, PM을 한꺼번에 몰기.

## 7. 근무표 편성 (교대·관제)

- 표준: **CP-SAT로 제약 모델링**(최소 인원, 연속 야간 상한, 근무 사이 휴식, 숙련도 조합, 희망 휴무는 부드러운 제약)
- 기준선: 순환 패턴(4조 3교대)을 만들고 사람을 패턴에 배정 → 예외만 수정
- 공정성 지표: 야간·주말 횟수의 최대−최소, 표준편차, 희망 반영률
- 함정: 규칙만 지키고 한 사람에게 불리한 근무 몰기, 휴가·인원이 적은 날(Happy Friday 등)

## 8. 배정·매칭

| 문제 | 방법 |
|---|---|
| 1:1 비용 최소 | **헝가리안**(`scipy.optimize.linear_sum_assignment`) |
| 용량 있는 배정 | 최소 비용 흐름, ILP, 그리디 + 맞바꾸기 |
| 선호가 양쪽에 있음 | **Gale–Shapley 안정 매칭** |
| 묶음 구성(HBM 다이 적층처럼 가장 나쁜 원소가 등급 결정) | 특성으로 정렬 후 비슷한 것끼리 묶기(정렬 묶음), 등급별 목표 수량에서 역배정, 지역 탐색 |

## 9. 추천

- 기준선: 인기순, 규칙(거리·영업시간 필터)
- 협업 필터링: item-item, implicit ALS / 콘텐츠 기반 점수
- 다양성·공정성: **MMR**(관련성과 중복 사이 균형), 노출 분산(한 곳에 쏠림 방지), 혼잡도 반영
- 지표: Precision@k·Recall@k·NDCG, 커버리지, 다양성. 오프라인 지표와 현업 만족은 다를 수 있다.

## 10. 블랙박스 최적화 (공정 조건, 하이퍼파라미터, 실험 예산)

| 방법 | 쓰임 |
|---|---|
| 라틴 하이퍼큐브·소볼 수열 | 첫 탐색을 고르게 |
| **베이지안 최적화**(GP + EI), **TPE(Optuna)** | 실험이 비쌀 때 다음 실험점 고르기 |
| CMA-ES | 연속 변수, 실험이 비교적 쌀 때 |
| DOE(부분 요인, 반응표면법) | 현업이 익숙한 설명 방식 |
| 밴딧(UCB, Thompson) | 선택지 중 좋은 것을 시험하면서 고르기 |

**함정:** 첫 좋은 점에서 멈춤(탐색 부족), 잡음 있는 측정의 한 번 결과를 믿기, 실험 예산 초과.

## 11. 수요 예측

- 기준선: **계절 나이브**(지난주 같은 요일), 이동 평균
- 강한 방법: ETS·ARIMA, 시차 특징 + LightGBM(M5 대회 상위권)
- 지표: MASE·sMAPE. 기준선 대비 개선을 보인다.

## 12. 군집

- k-means(수를 정해야 함), DBSCAN(밀도, 잡음 분리), 계층 군집
- 용량 있는 군집(버스·구역 묶기): k-means 후 용량 맞춰 재배정, 또는 sweep

---

**공통 체크**
1. 기준선과 강한 방법을 **같은 `evaluate`**로 비교했나
2. 퇴화 해(전부, 0개, 몰빵, 잘게 쪼개기)가 아닌가
3. 검증용 데이터를 따로 두었나(시간 순서면 뒤 기간)
4. 고른 방법을 `내 말:`로 설명할 수 있나
