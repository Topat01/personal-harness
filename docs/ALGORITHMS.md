# 문제 유형별 알려진 방법 (쉽게 보기)

> 쓰는 법: 과제가 아래 어느 유형인지 찾고, **① 먼저 할 것(기준선)**으로 끝까지 통하게 만든 뒤, **② 더 잘하려면**의 방법과 같은 `evaluate`로 비교한다. **③ 조심할 것**은 퇴화 해와 평가 함정, **④ 확인**은 Codex 결과가 맞는지 사람이 보는 방법(하한·작은 예제·다른 코드로 재계산)이다.
> 이름은 Codex에게 그대로 말하면 된다. 예: "기준선은 sweep, 비교 후보는 OR-Tools Routing으로."

---

### 1. 이상한 값 찾기 (설비 센서, 측정값, 로그)
> "평소와 다른 순간을 빨리, 덜 시끄럽게 잡기"

- **① 먼저:** 평소 범위를 정하고 벗어나면 알림. 평균 ± 3σ(SPC), 튀는 값에 덜 흔들리게 하려면 중앙값 기반(MAD)
- **② 더 잘하려면**
  - 조금씩 계속 밀리는 변화 → **CUSUM / EWMA**(누적해서 봄)
  - 모양이 이상한 구간 → **Matrix Profile**(비슷한 구간이 없는 곳 찾기)
  - 센서가 여러 개 → **PCA + T²/SPE**(반도체 공정 현업의 표준), **Isolation Forest**
- **③ 조심:**
  - 딥러닝이 단순한 방법을 못 이기는 경우가 흔하다. 꼭 비교한다.
  - 구간 안 한 점만 맞혀도 다 맞힌 걸로 치는 채점(point-adjust)은 점수를 부풀린다.
  - 알림이 너무 많으면 아무도 안 본다. 하루 알림 수도 지표로 둔다.
- **④ 확인:** 알려진 이상을 몇 개 직접 심은 데이터로 잡히는지, 정상 기간에 하루 알림이 몇 건인지

### 2. 원인 찾기 (수율 하락, 불량 증가)
> "불량 난 것들이 공통으로 겪은 게 뭐지?"

- **① 먼저:** **공통성 분석**. 불량 로트가 함께 거친 장비·챔버·시간대를 센다.
- **② 더 잘하려면:** 그룹별 불량률 비교 + 통계 검정(χ², Fisher). 여러 개를 동시에 검정하면 보정(BH). 트리 모델 + SHAP으로 후보 순위
- **③ 조심:** 표본 1~2개짜리 그룹의 0%·100%, 상관을 원인으로 착각, 같은 시기에 바뀐 게 여러 개(교란)
- **④ 확인:** 찾은 원인 그룹을 빼면 불량률이 실제로 내려가는지, 그룹별 표본 수를 함께 표시

### 3. 웨이퍼 맵 불량 모양 분류
> "불량이 가장자리에 링으로? 가운데? 긁힌 줄?"

- **① 먼저:** 모양 특징(중심에서 거리별 불량 비율, 덩어리 크기) + 랜덤 포레스트
- **② 더 잘하려면:** CNN
- **③ 조심:** 정상이 대부분이라 정확도가 높아 보인다. 모양별 재현율을 본다.
- **④ 확인:** 모양별 재현율과 혼동 행렬, 틀린 예시 몇 장을 눈으로 확인

### 4. 차량 경로 (셔틀, 물류, 순회)
> "여러 대로 여러 곳을 돌 때 대수와 시간을 줄이기"

- **① 먼저:** **sweep**(출발지 기준 각도 순으로 정원까지 채우기), **savings**(두 노선을 합쳐 줄어드는 거리가 큰 것부터)
- **② 더 잘하려면:** 지역 탐색(순서 바꾸기·옮기기·맞바꾸기), **OR-Tools Routing**
- **③ 조심:** 너무 잘게 쪼갠 노선(1명 버스), 최대 탑승 시간, A→B와 B→A 시간이 다름
- **④ 확인:** 하한 = ⌈총 인원 ÷ 정원⌉대. 노선 수가 하한의 몇 배인지, 손으로 푼 3~5명짜리 예제와 결과 일치

### 5. 배치·커버리지 (카메라, 센서, 정류장, 시설 위치)
> "적은 개수로 최대한 덮기"

- **① 먼저:** **그리디**. 지금 가장 많이 새로 덮는 자리부터 하나씩 고른다. 이론적으로도 꽤 좋다(최적의 약 63% 이상 보장).
- **② 더 잘하려면:** 고른 것과 안 고른 것을 맞바꿔 보기, 작은 문제는 정수계획으로 최적해 확인. 위험한 구역에 가중치
- **가격이 다르고 예산이 있으면:** "새로 덮는 칸 ÷ 가격"이 큰 것부터 고르는 그리디 + "예산 안에서 가장 좋은 하나짜리 선택"과 비교해 나은 쪽(이 조합이 알려진 근사 보장이 있다). 종류가 여러 개면 (위치 × 종류)를 후보 하나로 본다
- **어떤 지점은 k대 이상이 봐야 하면:** ① 필수 지점부터 k대를 채우는 그리디(제약 충족) → ② 남은 예산으로 커버리지 그리디 → ③ 맞바꾸기로 개선. 필수가 먼저, 개선은 나중
- **최소 커버리지(예: 70%)가 있으면:** 먼저 그 값을 넘기는 가장 싼 해를 찾고(제약 충족), 그다음 남는 예산으로 늘린다
- **③ 조심:** 전부 설치(비용 무시), 한쪽에 몰기, 두 카메라가 같은 곳을 볼 때 두 번 세기
- **④ 확인:** 상한 = 덮을 수 있는 전체 칸. 작은 예제는 전수 탐색 결과와 그리디가 같은지, 커버리지를 다른 코드로 다시 계산

### 6. 일정·순서 정하기 (장비 투입, 정비, Q-time)
> "무엇을 먼저 넣을까"

- **① 먼저:** 우선순위 규칙. 납기 빠른 순(EDD), 여유 시간 적은 순
- **② 더 잘하려면:**
  - 규칙 여러 개를 **시뮬레이션**으로 같은 상황에 돌려 비교
  - **OR-Tools CP-SAT**로 작은 문제의 최적 일정
  - Q-time이 있으면 뒤 공정 상황을 보고 앞 공정 투입을 늦추기
- **③ 조심:** 규칙만 지키려고 장비를 놀림, 낮은 우선순위가 영영 밀림, 정비를 한꺼번에 몰기
- **④ 확인:** 하한 = 총 작업 시간 ÷ 장비 수. 시뮬레이션 시간 순서가 맞는지(작업 겹침·음수 대기 0건)

### 7. 근무표 짜기 (교대, 관제, 클린룸)
> "규칙도 지키고 누구 하나 손해 안 보게"

- **① 먼저:** 4조 3교대 같은 순환 패턴을 만들고 사람을 패턴에 배정, 예외만 손보기
- **② 더 잘하려면:** **CP-SAT**에 규칙을 제약으로 넣기(최소 인원, 연속 야간 상한, 근무 사이 휴식, 숙련자 최소 1명, 희망 휴무)
- **③ 조심:** 한 사람에게 야간·주말 몰기 → 공정성 지표(최대−최소 횟수), 인원이 적은 날(휴가, Happy Friday)
- **④ 확인:** 모든 날짜·근무에 대해 최소 인원·연속 근무·휴식 규칙을 별도 함수로 전수 검사, 사람별 근무 횟수 분포

### 8. 짝짓기·배정 (사람↔일, 다이↔스택)
> "누구를 어디에"

- **① 먼저:** 그리디(비용 작은 짝부터)
- **② 더 잘하려면**
  - 1:1 최소 비용 → **헝가리안**(scipy에 있음)
  - 양쪽에 선호가 있음 → **안정 매칭(Gale–Shapley)**
  - 묶음의 등급이 가장 나쁜 원소로 정해짐(HBM 적층) → 특성 순으로 정렬해 비슷한 것끼리 묶기, 목표 등급 수량에서 거꾸로 배정
- **③ 조심:** 좋은 것을 앞쪽에 몰아 뒤쪽이 다 탈락
- **④ 확인:** 1:1이면 모든 대상이 정확히 한 번, 작은 예제는 전수 탐색과 비용 비교

### 9. 추천 (식당, 교육, 사례)
> "좋아할 만한 것을, 한쪽에 쏠리지 않게"

- **① 먼저:** 인기순 + 조건 필터(거리, 영업시간)
- **② 더 잘하려면:** 비슷한 사람·항목 기반(협업 필터링), 내용 기반 점수. 다양성은 **MMR**(비슷한 것 반복 줄이기)
- **③ 조심:** 늘 같은 곳 추천, 인기 쏠림으로 혼잡. 다양성·커버리지도 지표로 둔다.
- **④ 확인:** 추천 결과 상위 몇 개를 담당자 기준으로 납득되는지, 한 항목 노출 비율 상한

### 10. 실험 횟수가 정해진 최적화 (공정 조건, 설정값)
> "몇 번밖에 못 해 보는데 가장 좋은 조건 찾기"

- **① 먼저:** 범위를 고르게 훑기(라틴 하이퍼큐브), 좋은 곳 주변을 좁혀 보기
- **② 더 잘하려면:** **베이지안 최적화 / Optuna(TPE)**(지금까지 결과로 다음 시험할 곳 고르기), 선택지가 몇 개면 밴딧
- **③ 조심:** 첫 좋은 결과에서 멈춤, 잡음 있는 측정 한 번을 믿기, 예산 초과
- **④ 확인:** 같은 조건을 두 번 측정해 잡음 크기 확인, 예산(실험 횟수) 카운터

### 11. 수요 예측
- **① 먼저:** 지난주 같은 요일 값(계절 나이브)
- **② 더 잘하려면:** ETS·ARIMA, 지난 값들을 특징으로 넣은 LightGBM
- **③ 조심:** 기준선보다 나은지 꼭 숫자로 보인다.
- **④ 확인:** 뒤 기간을 떼어 두고 계절 나이브와 오차 비교

### 12. 묶기 (구역, 그룹)
- **① 먼저:** k-means(개수 정함), 정원이 있으면 묶은 뒤 넘치는 것 옮기기 또는 sweep
- **② 더 잘하려면:** DBSCAN(밀집한 곳만 묶고 외딴 점 분리)
- **④ 확인:** 묶음별 크기 분포(정원 초과·1~2개짜리 0건), 지도나 그래프로 한 번 눈으로

---

**어느 유형이든 마지막 확인 네 가지 (부록 포함)**
1. 기준선과 더 나은 방법을 **같은 `evaluate`**로 비교했나
2. 퇴화 해(전부, 0개, 몰빵, 잘게 쪼개기)가 아닌가
3. 검증용 데이터를 따로 두었나(시간 순서면 뒤 기간)
4. 고른 방법을 `내 말:`로 설명할 수 있나

### 13. 웨이퍼 이송(OHT) 경로·혼잡
> "레일 위 수백 대가 막히지 않게"
- **① 먼저:** 최단 경로(Dijkstra) + 가까운 빈 차량 배정, 이벤트 시뮬레이션으로 대기·이송 시간 측정
- **② 더 잘하려면:** 혼잡할수록 구간 가중치를 올려 우회(동적 가중치), 앞으로 올 요청을 보고 빈 차량 미리 보내기
- **③ 조심:** 혼잡 무시(전부 최단 경로), 차량을 세워 혼잡 0. 긴급 로트 기아
- **④ 확인:** 하한 = 최단 경로 이송 시간. 시뮬레이션에서 같은 구간 동시 점유 규칙 위반 0건, 요청 수 = 처리 수 + 대기 수

### 14. 정비 일정 + 부품 재고
> "고장 위험, 생산 손실, 재고 비용 사이 균형"
- **① 먼저:** 장비별 고장 간격(MTBF)으로 위험 계산, 생산이 적은 시간대에 PM. 재고는 (s, S) 재주문
- **② 더 잘하려면:** 와이블 분포 위험, 간헐 수요 예측(**Croston·TSB**), 정비 계획에 맞춘 부품 준비
- **③ 조심:** 전부 미루기·당기기, 재고 0·과잉. 장비 1시간 정지 손실을 담당자에게 확인
- **④ 확인:** 과거 기간을 다시 돌려(백테스트) 결품 횟수·재고 금액을 현재 규칙과 비교

### 15. 레이아웃 배치
- **① 먼저:** 물동량이 큰 쌍부터 가깝게 두는 그리디
- **② 더 잘하려면:** 맞바꾸기 지역 탐색, 모의 담금질(이차 할당 문제 QAP)
- **③ 조심:** 크기·안전 거리 제약, 한곳에 몰려 혼잡
- **④ 확인:** 제약(겹침·안전 거리) 위반 0건, 총 이송 거리를 다른 코드로 재계산

### 16. 기록 정합 (시스템 기록 ↔ 실제)
- **① 먼저:** 키 정규화 → 후보 생성 → 점수 → 1:1 배정(헝가리안)
- **② 더 잘하려면:** 시간 창 다수결로 신호 잡음 줄이기, 불확실한 건 사람 확인 대기열
- **③ 조심:** 전부 일치 처리 / 전부 사람에게 넘김
- **④ 확인:** 사람이 맞춘 표본 20~30건으로 정밀도·재현율, 1:1 위반 0건

### 17. 예측 모델의 노후(drift) 대응
- **① 먼저:** 이동 창 재학습
- **② 더 잘하려면:** 정비(PM) 이벤트에 맞춘 리셋, 불확실성이 크면 실측 샘플링 늘리기
- **③ 조심:** 과거 전체로 한 번 학습하고 끝내기
- **④ 확인:** 시간 순서로 나눠 재학습 정책별 오차 비교, PM 전후 오차 변화
