# final-docs

## 1. 실제 결과로 맞추기 (문서를 쓰기 전에)
- 테스트와 대표 실행(서버면 헬스체크·로그인·핵심 기능 1회, 사람이 확인한 결과가 있으면 그것도)을 **지금 다시** 돌린다.
- **테스트가 실패하면 문서로 해명하지 말고** 원인을 고치거나 사람에게 묻는다. `git log --stat`으로 최근 커밋이 산출물(exports 등)을 바꿔 테스트를 깬 것이 아닌지 본다. 테스트는 서비스가 덮어쓰는 파일에 기대지 않게 한다.
- 그 결과로 `NOTES.md` 4~7절의 옛 정보(예: "확인 못 함", "저장 중단")를 고치고, `SPEC.md` H·R 상태를 `[x]`(어떻게 확인했는지) / `NOT_RUN` / `[ ]`로 갱신한다.
- 문서끼리 같은 항목(테스트 수, 서버 확인 여부, 지표 숫자)이 다르면 마무리하지 않는다.

## 2. 지시문이 요구한 문서를 모두 쓰기
- 양식(제목·순서)이 주어졌으면 그대로 쓰고, 해당 없는 항목은 "해당 없음". 지시문 파일 자체는 수정하지 않는다.
- 실행 안내: 다른 사람이 처음부터 따라 할 수 있는 설치·환경변수(값 제외)·실행·접속·테스트 명령, **빈 상태에서 결과를 보기까지의 순서**(예: 먼저 생성해야 내보내기가 된다), 역할별 이용 순서, 데이터 준비·오류 확인 방법, 판단 기준과 최적화 방식(NOTES 2절의 비교 수치).
- AI 협업 문서: NOTES 6절 [AI] 줄의 실제 사례로 쓴다(무엇이 문제였고, 어떻게 알아챘고, 어떻게 확인·해결했나). 질문이 여러 개면 **질문마다 서로 다른 실제 사례**를 쓴다. "AI가 틀린 사례"를 묻는 질문에 사람의 판단 기록을 대신 쓰지 않는다. 일반론 금지.
- 확인하지 않은 내용은 쓰지 않는다. 사람이 정한 것(C번호)과 내가 가정한 것(`가정:`)과 AI가 제안한 것을 구분한다.

## 3. 예상 질문 (NOTES.md 8절)
먼저 **사건 카드 3장**: NOTES 6절과 `git log`에서 가장 큰 오류·변경 3개를 골라 각각 5줄(증상 → 원인과 파일:함수 → 바꾼 파일과 버린 방법 → 확인: 재현 재실행·회귀 확인 → 영향 범위·남은 위험)로 쓴다. 제출 후 질문은 작업 기록에 남은 이런 사건을 구체적으로 묻는다.
아래 6유형마다 질문 1개와 **핵심어 3~4개**(파일·함수 이름, 숫자, 버린 방법, 약한 곳)만 쓴다. 답 문장은 쓰지 않는다(사람이 말해 본다). 평가자가 찌를 약점(예: 큰 비율로 남은 한계, 우선순위 1번 지표의 미달)을 피하지 말고 질문으로 만든다.
1. 모듈 간 동작과 경계 2. 테스트와 다른 사람의 재현 3. 운영 중 중복 요청·처리 중 실패 4. 기초안→개선안 이유와 효과 5. 까다로운 엣지케이스 6. AI가 만든 코드에서 검증·발견한 것
그리고 **전제가 틀린 질문** 하나(예: 하지 않은 일을 했다고 가정하는 질문)를 만들어, 어떻게 정정할지 핵심어를 적는다.

## 4. 발표 요지 (NOTES.md 9절)
발표·질의응답용 6줄. 각 줄은 한 문장이고 숫자와 근거(C번호)를 넣는다.
문제 정의 → 판단 기준과 이유 → 기초안 → 개선안과 비교 숫자 → 검증 방법(AI가 틀린 것을 잡은 사례 1개, 숫자 포함) → 남은 한계와 현업이라면 다음에 확인할 것.
**현업 효과는 반드시 숫자 1개 + 환산 가정**으로 쓴다: 담당자 기준선(현재 방식)과 같은 단위로 바꾼다(예: "하루 편도 112노선 ≈ 왕복 56대 가정 시 현재 140대 대비 −○대"). 비율 지표는 분모를 함께 쓴다.

## 5. 따라가기 안내서 (NOTES.md 3절)
대표 흐름 하나(사용자 동작 → 모듈 → 결과)를 처음부터 끝까지 **선형 안내서**로 쓴다. 단계마다 `파일:줄`과 실제로 실행한 명령의 출력 한두 줄을 넣는다. 20줄 이내.

## 6. 점검과 퀴즈
- `python3 <kit>/tools/check_submit.py <필수 산출물…>`(Dockerfile이 있으면 `--docker`) 실행 결과를 보고한다. 컨테이너를 못 띄우면 Dockerfile이 지금 소스·데이터를 모두 포함하는지 직접 대조한다.
- `NOTES.md`의 빈칸(현재 상태·마지막 커밋, 3절 대표 흐름, 6절 [엣지]·[장애])과 원시 출력 덤프를 찾아 채우거나 지운다. 사람만 알 수 있는 것은 목록으로 물어본다.
- 마지막으로 확인 퀴즈(AGENTS 4절)를 3문항 낸다. 틀린 문항은 8절에 "내가 헷갈린 것"으로 남긴다.
