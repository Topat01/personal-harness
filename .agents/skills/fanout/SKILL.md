# fanout (나눠 맡기기)

1. **계약 먼저:** `NOTES.md` 2절 모듈 표에 이번에 나눌 부분의 함수 이름, 입력 → 출력 형식(작은 JSON 예시), API 경로, 파일 경로를 적는다. 계약이 없으면 나누지 않는다.
2. **나눌 수 있는지 확인:** 작업마다 고칠 파일이 겹치지 않아야 한다. 겹치면 순서대로 한다.
3. **작업마다 브리프**(서브에이전트에 그대로 넘긴다):
   - 목표 한 줄과 완료 조건(실행할 명령과 기대 출력)
   - 고쳐도 되는 파일 / 읽기만 할 파일 / 건드리면 안 되는 파일
   - 지켜야 할 계약(1번)과 관련 SPEC 항목 번호
   - 금지: 새 의존성, 커밋, 계약 변경, 요구에 없는 제약 추가
   - 테스트 최대 개수(기본 1~2개), 시간 상한(기본 20분, 넘으면 중간 결과 보고)
   - 끝나면: 바꾼 파일, 실행 명령과 출력, `가정:` 목록, 약한 곳 한 줄
4. 서브에이전트를 쓸 수 없으면 사람에게 "두 번째 터미널에서 `codex`를 열고 아래 브리프를 붙여 넣어 달라"고 브리프를 출력한다.
5. **합치기(메인):** 결과마다 직접 실행해 완료 조건을 확인 → 계약 위반이 있으면 고쳐 달라고 돌려보낸다 → 합친 뒤 전체 흐름을 한 번 실행 → `SPEC.md` 상태 갱신 → AGENTS.md 4절 설명(작업별 3줄) → 메인이 커밋한다.
6. 진행 중에는 사람에게 "누가 무엇을 하는 중인지" 한 줄씩 보여 준다. 사람은 그동안 담당자와 대화하거나 `NOTES.md`를 읽는다.
