# fanout (나눠 맡기기)

1. **계약 먼저:** `NOTES.md` 2절 모듈 표에 이번에 나눌 부분의 함수 이름, 입력 → 출력 형식(작은 JSON 예시), API 경로, 파일 경로를 적는다. 계약이 없으면 나누지 않는다.
2. **나눌지는 네가 판단한다**(사람은 시간을 가늠하지 않아도 된다). 아래를 **모두** 만족하는 작업만 서브에이전트로 보내고, 나머지는 메인이 순서대로 한다. 판단 결과를 한 줄로 보고한다(예: "화면·데이터셋은 나눔, 보고서는 작아서 메인").
   - 새 파일을 만들거나 다른 작업과 겹치지 않는 파일만 고친다
   - 요구(R) 2개 이상, 또는 화면 하나 전체, 또는 해법 후보 하나 전체를 다룬다
   - 계약(1번)만 보고 혼자 끝낼 수 있다(중간에 사람·담당자 답이 필요 없다)
   나눌 작업이 하나뿐이면 서브에이전트를 쓰지 않고 메인이 바로 한다(사람은 그동안 담당자와 대화한다).
3. **작업마다 브리프**(서브에이전트에 그대로 넘긴다):
   - 목표 한 줄과 완료 조건(실행할 명령과 기대 출력)
   - 고쳐도 되는 파일 / 읽기만 할 파일 / 건드리면 안 되는 파일
   - 지켜야 할 계약(1번)과 관련 SPEC 항목 번호
   - 금지: 새 의존성, 커밋, 계약 변경, 요구에 없는 제약 추가
   - 테스트 최대 개수(기본 1~2개), 시간 상한(기본 20분, 넘으면 중간 결과 보고)
   - 끝나면: 바꾼 파일, 실행 명령과 출력, `가정:` 목록, 약한 곳 한 줄
4. 서브에이전트를 쓸 수 없으면 사람에게 "두 번째 터미널에서 `codex`를 열고 아래 브리프를 붙여 넣어 달라"고 브리프를 출력한다.
5. **새 맥락 리뷰**(`submittable-v1` 직전과 마무리 직전): 리뷰 전용 서브에이전트에게 `git diff`(또는 첫 커밋 이후 전체)와 `SPEC.md`를 주고, 빠진 H·R, 요구에 없는 기능·제약(**거부·오류를 내는 조건마다 지시문 근거가 있나**), 위험(데이터 손실·권한), **같은 키 중복 입력이 집계를 부풀리지 않나**, **같은 요청 두 번·생성이 수동 편집을 덮어쓰기**, **서버 전역 상태가 요청 사이에 남지 않나**, **후보·what-if가 실제로 실행됐나(NOT_RUN)**만 목록으로 받는다. 리뷰어는 고치지 않는다. 메인이 고칠지 사람에게 묻는다.
6. **합치기(메인):** 결과마다 직접 실행해 완료 조건을 확인 → 계약 위반이 있으면 고쳐 달라고 돌려보낸다 → 합친 뒤 전체 흐름을 한 번 실행 → `SPEC.md` 상태 갱신 → AGENTS.md 4절 설명(작업별 3줄) → 메인이 커밋한다.
7. 진행 중에는 사람에게 "누가 무엇을 하는 중인지" 한 줄씩 보여 준다. 사람은 그동안 담당자와 대화하거나 `NOTES.md`를 읽는다.
