# unit-explain

## 절차
1. 이번 단위의 변경을 본다: `git diff --stat`과 바뀐 함수만(파일 전체를 읽지 않는다).
2. 테스트를 실행해 결과를 확인한다(이미 이번 단위에서 실행했으면 그 출력을 쓴다).
3. 아래 형식으로 보고한다. 파일·함수 이름을 반드시 쓴다.

## 출력
```
하는 일(3줄): 
이 패턴을 쓴 이유: (예: 정렬 후 직전 값과 비교 — 입력 순서가 섞여 있어서)
버린 대안과 이유:
틀리는 입력 2개: ① 입력/상황 → 현재 동작  ② …
검증: (테스트 이름, 통과 수, 커밋 예정 메시지)
DECISIONS 한 줄 초안: | D? | 결정 | 근거(C?) | 버린 대안 | 검증 |
```

## 규칙
- 사람은 이 보고를 읽고 **자기 말로 고쳐서** DECISIONS에 적는다. 그대로 붙여 넣으라고 권하지 않는다.
- 틀리는 입력을 찾았는데 요구 범위 안이면 그 자리에서 사람에게 알린다(고칠지, 한계로 남길지 사람이 정한다).
