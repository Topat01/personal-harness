# interview-prep

## 입력
- 과제 안내의 목표·필수조건·제출물
- `scan.py` 출력(파일 구성, 기존 코드·테스트), 데이터가 있으면 `eda.py`의 "질문 거리"
- `PLAN.md`의 "확인한 조건"(이미 답을 받은 것은 제외)

## 절차
1. 요구사항을 한 줄씩 나열하고, 각 요구에서 **해석에 따라 결과가 달라지는 지점**을 찾는다. 과제 유형별로 흔한 지점:
   - 데이터 처리·분석: 대상 범위·기간, 계산식·정의, 제외 규칙, 묶기·정렬, 단위·시간 기준
   - 기존 코드 수정: 기대 동작과 현재 동작의 차이, 바꾸면 안 되는 동작(호환성), 재현 조건
   - 서비스·도구: 누가 어떤 상황에서 쓰는지, 필수 화면·입력·출력, 오류일 때 보여 줄 것
   - 문서 기반 응답: 근거로 써도 되는 문서 범위, 문서에 없을 때 답하는 방식, 문서끼리 충돌할 때
   - 공통: 성공 기준(숫자·현재값·측정 방법), 결과를 누가 어디서 보는지, 이번에 하지 않아도 되는 것
2. 질문 후보를 **최대 10개**, 답에 따라 결과가 크게 달라지는 순서로 쓴다.
3. 애매한 규칙은 **실제 사례**(행 ID와 값, 파일·함수, 화면, 입력 예)를 넣어 묻는다.

## 출력 형식
```
| 순위 | 대상(파일·컬럼·값·함수·화면) | 질문(한 문장, 해법 단어 없이) | 답에 따라 무엇이 달라지나 |
```

## 금지
- 한 질문에 대상 두 개 이상, "요구사항 다 알려 주세요"·"주의할 점은?" 같은 막연한 질문.
- 담당자의 답을 추측해 조건으로 쓰기. 답은 사람이 `PLAN.md`에 기록한다.
- 메신저 말투로 길게 다듬기. 사람이 직접 짧게 고쳐 보낸다.
