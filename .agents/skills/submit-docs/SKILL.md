# submit-docs

## 절차
1. 근거를 모은다(실행해서 출력을 본다).
   - `git log --format='%h %s' <시작 커밋>..HEAD`
   - 테스트 명령 실행 결과(통과 수, 실패 수)
   - `PLAN.md`의 확인한 조건(C1…)과 `DECISIONS.md`의 결정(D1…)
   - 핵심 산출물의 건수·수치(스크립트로 다시 계산)
2. 과제가 제출 문서 파일명을 정했으면 그 이름을 쓴다. 아니면 `SUBMIT.md`.
3. 아래 구조로 쓴다.
   - `## 선택한 판단과 근거`: 판단 / 근거(조건 ID·데이터 사실) / 버린 대안 / 증거(커밋 해시) 표. 담당자가 정한 것과 내가 정한 것을 구분한다.
   - `## 검증 결과`: 실제로 실행한 명령과 결과만. 입력 N행 → 사유별 제외 → 결과 M건. 독립 재계산 결과. 실행하지 않은 것은 `NOT_RUN`.
   - `## 남은 한계`: 알고 있는 결함과 확인하지 못한 가정을 먼저 정직하게 쓴다. 결과가 틀리는 입력 2개 이상.
   - 끝에 `재현:` 한 줄 명령, `사용한 공개 하네스:`(저장소 주소@커밋, 무엇에 썼는지), `버린 접근:`, `AI가 틀렸던 곳과 잡은 방법:`.
4. 초안을 쓴 뒤 문서의 수치·파일명·함수명이 실제 코드·출력과 맞는지 대조하고, 다른 곳을 보고한다.
5. `python3 ~/kit/tools/check_submit.py <필수 제출물…> [--doc 문서명]`을 실행해 결과를 보고한다.

## 금지
- "완벽히", "모든 경우" 같은 근거 없는 표현.
- 실행하지 않은 검증을 실행했다고 쓰기.
- 사람이 내린 판단을 AI가 정한 것처럼, 또는 그 반대로 쓰기.
