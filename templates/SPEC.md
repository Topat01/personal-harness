# SPEC — 만들어야 하는 것 (지시문에서 뽑은 요구와 확인할 것)

> 지시문이 원본이다. 여기는 빠뜨리지 않으려는 체크 목록이다. 숫자·파일명·용어는 지시문 그대로 적는다.
> 상태: `[ ]` 아직 / `[~]` 일부 / `[x]` 확인함(어떻게) / `NOT_RUN` 실행 못 함

## 1. 한눈에
- 만들 것(한 문장):
- 필수 산출물(파일명 그대로):
- 실행 환경 요구(언어·포트·컨테이너·저장소 등):
- 하지 않는 범위(지시문에 적힌 것):

## 2. 지켜야 할 규칙 (어기면 결과가 틀린 것)
| ID | 묶음 | 규칙(숫자 그대로) | 우선 | 지시문 위치 | 어떻게 검사하나(validate 항목) | 상태 |
|---|---|---|---|---|---|---|
| H1 | | | P0 | | | [ ] |

## 3. 요구 목록 (기능·화면·문서)
| ID | 요구(한 줄) | 우선 | 지시문 위치 | 완료 판단(무엇을 보면 됐다고 하나) | 상태 |
|---|---|---|---|---|---|
| R1 | | P0 | | | [ ] |

## 4. 열려 있는 것 → 담당자 확인
지시문이 정하지 않았거나 "담당자에게 확인"하라고 한 것. 질문은 사람이 쓴다.
| ID | 무엇이 열려 있나 | 답에 따라 달라지는 것 | 질문(사람) | 답 → C번호 | 반영(R/H/기준) |
|---|---|---|---|---|---|
| Q1 | | | | | |

답은 `NOTES.md` 1절 C표에도 한 줄로 옮긴다. 대상마다 값이 다른 답(건물·층별 등)은 `facts/<이름>.csv`에 행으로 쌓고, C표에는 파일 이름만 적는다.
